# PROPUESTA COMERCIAL DE SOFTWARE NATIVO
## Sistema de Gestión para una Academia Deportiva

**Versión:** 1.0  
**Fecha:** 19 de agosto de 2026  
**Modelo:** Licencia para una sola academia, instalada localmente

---

## 1. Alcance del modelo nativo

El software nativo se instala en una computadora o servidor bajo control de la academia. La licencia se concede para una única academia y no requiere una suscripción mensual obligatoria ni conexión permanente a Internet.

Este modelo es adecuado para una institución que desea realizar una inversión inicial, mantener sus datos localmente y operar con una estructura estable. El acceso desde otras computadoras depende de la instalación en una red local o de una configuración técnica adicional.

## 3. Módulos incluidos en la licencia integral

- Gestión académica: alumnos, tutores, categorías, inscripciones e historial.
- Gestión deportiva: equipos, entrenamientos, asistencias, campeonatos, partidos y calendario.
- Gestión financiera: obligaciones, pagos, recibos, caja, movimientos y reportes.
- Inventario y ventas: productos, compras, ventas, stock y devoluciones.
- Usuarios, roles, permisos y auditoría.
- Generación de documentos, exportaciones y respaldos locales.
- Configuración de nombre, logo, colores y datos de la academia.

## 6. Reglas para desactivar módulos

En el modelo nativo, desactivar un módulo no elimina los datos. El módulo queda bloqueado para nuevas operaciones, pero los registros históricos pueden conservarse y consultarse según la configuración de la licencia.

El Núcleo Base siempre debe permanecer activo. Además, se aplican estas dependencias:

| Grupo que debe permanecer unido | Razón operativa |
|---|---|
| Académico + categorías e inscripciones | Los módulos deportivo, asistencia y financiero necesitan alumnos identificados y clasificados. |
| Obligaciones + pagos | El pago necesita una obligación para calcular saldo, deuda y estado de cuenta. |
| Pagos + caja | Cada pago debe poder reflejarse en caja y en la auditoría financiera. |
| Inventario + compras + ventas | Las compras aumentan stock y las ventas lo reducen; separar el flujo daña el control de existencias. |
| Usuarios + roles + permisos + auditoría | El control de acceso y la trazabilidad forman una única función de seguridad. |

### Desactivaciones permitidas

- Desactivar Deportivo, manteniendo Académico y Financiero.
- Desactivar Inventario y Ventas, manteniendo los demás módulos.
- Mantener Académico sin contratar Deportivo ni Inventario.

### Desactivaciones no permitidas

- Desactivar Académico y mantener Deportivo, Asistencia o Inscripciones.
- Desactivar Obligaciones y mantener Pagos.
- Desactivar Caja mientras existan Pagos activos.
- Desactivar Compras y mantener Ventas o control de stock.
- Desactivar Auditoría, Usuarios o Permisos del Núcleo Base.

## 7. Responsabilidades de la academia

- Mantener el equipo, sistema operativo y red local en condiciones adecuadas.
- Realizar respaldos periódicos en una ubicación externa a la computadora principal.
- Proteger las credenciales de los usuarios.
- Controlar quién tiene acceso físico al equipo y a la base de datos.
- Cumplir las obligaciones legales relacionadas con datos personales, especialmente los datos de menores.

## 8. Recomendación comercial

Para una academia pequeña o mediana se recomienda ofrecer dos alternativas:

1. **Licencia Inicial:** Núcleo Base + Académico por USD 960 iniciales.
2. **Licencia Integral:** todos los módulos por USD 1.740 iniciales.

La Licencia Integral tiene mayor valor para la institución porque evita futuras reinstalaciones, migraciones y ampliaciones de base de datos. El mantenimiento anual de USD 360 puede ofrecerse desde el segundo año, sin convertirlo en una obligación para continuar usando la versión adquirida.

> Los valores son una propuesta comercial inicial. Deben ajustarse según costos de instalación, soporte, impuestos, desplazamiento, alcance de la capacitación y nivel de personalización solicitado.
